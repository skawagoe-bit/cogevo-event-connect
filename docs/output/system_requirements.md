# システム要件定義書

## システム概要
本システム「CogEvo Event Connect」は、展示会や学会に出展する営業担当者の「商談後事務作業の多忙」と「追客の質のバラつき」という課題を解決するためのモバイルアプリケーションです。商談直後のわずか30秒で名刺・バッジのスキャンと属性入力を完了させ、SansanやUTAGEといった外部ツールへ即座にデータを連携します。さらに、その日の夜に1タップでパーソナライズされたお礼メール、1週間限定の「脳体力チェッカー」体験URL、および職種別のコミュニティ招待を送信することで、商談の熱量を逃さず成約へと繋げることを目的としています。

1. システムの目的
   - 展示会現場でのデータ入力ストレスと事務作業時間の最小化（50%削減目標）
   - 商談直後の迅速かつパーソナライズされたフォローアップによる成約率の向上
   - プロダクト体験（脳体力チェッカー）と職種別コミュニティを通じたユーザーのファン化

2. 主な機能
   - **マルチ・スキャナー（OCR）**: 名刺および学会バッジから情報を即座に読み取るコア機能。
   - **外部ツール連携**: Sansanへの名刺・メモ登録およびUTAGEへの配信リスト自動登録。
   - **夜の一斉送信**: 属性別に最適化されたフォローメールを一括送信する機能。
   - **体験URL・コミュニティ誘導**: 1週間限定の体験URL発行と属性に応じた専門コミュニティへの招待リンク挿入（差別化機能）。
   - **属性/セグメント選択**: 現場のニーズに合わせた職種（医師/PT/OT/ST等）や見込み度合いのワンタップ選択。

3. 提供する価値
   - **ユーザー（来場者）**: 商談の記憶が新しいうちに、自身の職種に特化した活用事例やプロダクト体験に触れられる。
   - **ビジネス（出展企業）**: 営業担当者が事務作業から解放され、戦略的な顧客フォローに集中できる。データの即時資産化。
   - **社会的価値**: 専門職同士の知見共有（コミュニティ）を促進し、地域医療・ケアの質の向上に寄与する。

4. 実現方法の概要
   - 現場での機動力を重視したモバイルファーストの Web アプリケーション（PWA）またはネイティブアプリ。
   - 高精度な OCR ライブラリまたは API を活用した情報取得。
   - 外部 CRM/MA ツール（Sansan, UTAGE）との API インテグレーション。
   - Vercel サーバーレス環境によるスケーラブルな基盤。

## 情報の前提と仮定
- **分析ソース**: `/docs/input` 以下のビジネス要件、プロダクト要件、機能一覧、MVP範囲、UI/UX方針、ターゲットユーザー、ユーザーフロー、およびシステム概要（A4一枚まとめ）を参照。
- **仮定**: 
  - 初期ユーザーは自社の営業・開発担当者（10-20名程度）から開始し、将来的には代理店などを含めた1,000人規模まで拡張することを想定。
  - 会場内の通信環境は不安定であることを考慮し、初期段階ではオンライン前提とするが、将来的にオフライン保存機能を検討する。

## 機能要件
- **イベントプリセット管理**: 当日のイベント名や属性マスタ（選択肢）を事前に設定・保持する。
- **OCRスキャン機能**: カメラを用いて名刺およびバッジから「氏名」「社名」「メールアドレス」「所属」を抽出する。
- **音声メールアドレス入力**: キーボード入力が困難な状況下で、音声によりメールアドレスを入力・テキスト化し、補正確認を行う。
- **外部サービス連携**:
    - **Sansan**: 取得したデータを名刺情報としてAPI経由で即時登録。
    - **UTAGE**: 属性に応じた配信シナリオにメールアドレスを追加。
- **フォローアップ送信管理**: 本日の登録者リストを表示し、内容の最終確認および一括メール送信を実行する。
- **期間限定URL生成**: 有効期限（168時間）を持つ体験用URLを生成し、メール本文に埋め込む。
- **ギフト提供ログ**: 特定の会員証提示に対するギフト（ノベルティ等）の提供記録を保存する。

## 非機能要件
- **パフォーマンス**:
  - スキャン開始から登録完了までの操作を「30秒以内」で完了できる軽量なUI。
  - 主要画面の遷移およびAPIレスポンスは3秒以内を目指す。
- **セキュリティ**:
  - Sansan/UTAGE の API キーはサーバーサイドで秘匿化し、暗号化して管理する。
  - 個人情報の保持は最小限とし、外部連携後は速やかに安全な状態で管理する。
- **可用性・拡張性**:
  - 展示会開催時間中（日中）の高負荷に耐えられるスケーラビリティ。
  - Vercel のオートスケーリング機能を活用する。
- **ユーザビリティ**:
  - 騒音や疲れのある現場を想定し、片手で操作可能な大きなボタンと高いコントラストのデザイン。

## 技術スタック
推奨される技術スタックとその妥当性は以下の通りです。

- **フロントエンド:** Next.js 16 (React) / Tailwind CSS
  - **理由**: 高速なページ遷移とレスポンシブ対応が容易。PWA化することでモバイルアプリに近い操作性を提供できる。
- **言語:** TypeScript
  - **理由**: 大規模開発やAPI連携における型安全性の確保。
- **バックエンド:** Next.js 16 App Router (Serverless Functions)
  - **理由**: フロントエンドとシームレスに開発でき、API連携ロジックを安全にサーバーサイドで実行可能。
- **データベース:** Supabase (PostgreSQL)
  - **理由**: リアルタイム機能（登録状況の確認）や認証、開発スピードの速さを評価。
- **認証:** Clerk (または Supabase Auth)
  - **理由**: 営業担当者向けのセキュアな認証を迅速に構築可能。
- **ホスティング:** Vercel
  - **理由**: Next.js との親和性が高く、デプロイの自動化とグローバルな配信速度に優れる。

## 開発ロードマップ
1. **Phase 1: MVP開発 (1ヶ月)**
   - 名刺・バッジOCRの基本機能実装。
   - Sansan/UTAGE への API 連携。
   - 夜の一斉送信（テンプレート固定）の実装。
   - 目的：現場の事務作業削減効果の検証。
2. **Phase 2: 機能拡充 & 安定化**
   - オフラインモードの実装（電波の悪い会場対策）。
   - 音声メモのAI要約機能の追加。
   - 目的：操作性の向上とデータ品質の改善。
3. **Phase 3: 分析 & スケール**
   - 詳細なクリック分析ダッシュボードの実装。
   - 代理店向けマルチテナント対応。
   - 目的：成約率向上のためのデータ活用と利用範囲の拡大。

## リスク分析
- **技術的リスク**: 会場の電波状況による通信エラー。
  - **対策**: 将来的なオフラインモードの実装と、送信エラー時の再試行キューイング。
- **ビジネス的リスク**: Sansan/UTAGE の API 仕様変更による連携停止。
  - **対策**: 疎結合なインターフェース設計と、主要ツールのSDK/APIドキュメントの常時監視。
- **法的/コンプライアンスリスク**: 名刺情報の取り扱いと個人情報保護。
  - **対策**: 利用規約の整備と、Sansan等のセキュリティ基準に準拠したデータ管理。
- **運用的リスク**: 現場での操作ミスによる誤送信。
  - **対策**: 送信前の最終確認ステップ（プレビュー機能）の徹底。

## UI/UXの方向性
- **デザインコンセプト**: 「爆速（Lightning Speed） & ミス・ゼロ（Zero Error）」
- **トーン＆マナー**: プロフェッショナルかつ誠実（CogEvoブルーを基調）、かつ操作を促すアクセントカラー。
- **ターゲットデバイス**: モバイル（スマートフォン）専用
- **参考サイト/アプリ**:
  - **Sansan**: OCRの操作フロー
  - **Linear**: 高速な操作感とミニマルなデザイン
  - **Slack/Discord**: コミュニティ誘導の体験設計
