# 開発計画書

## 1. 目的
本ドキュメントは、CogEvo Event Connectの開発におけるロードマップ、タスク分解（WBS）、およびリスク管理計画を定義する。

## 2. 開発ロードマップ

### Phase 1: MVP (Minimum Viable Product) 開発
- **目標**: 展示会での主要フロー（スキャン・登録・一斉送信）を完遂できること。
- **期間**: 4週間
- **マイルストーン**:
  - Week 1: インフラ構築、認証、DB設計
  - Week 2: OCR連携、カメラ機能、基本入力画面
  - Week 3: Sansan/UTAGE連携、一斉送信ロジック
  - Week 4: オフライン対応、最終調整、デプロイ

### Phase 2: v1.0 (機能拡張)
- **目標**: 精度向上とユーザー分析機能の追加。
- **機能**:
  - AIによる音声メモ要約
  - クリックトラッキング機能（体験URLの開封通知）
  - 管理者用ダッシュボード（全ユーザーの登録数集計）

## 3. タスク分解 (WBS)

### 3.1 基盤構築
- [ ] Vercel プロジェクト作成・環境変数設定
- [ ] Supabase プロジェクト作成・DBスキーマ適用 (RLS設定含む)
- [ ] Clerk 認証基盤の実装 (ログイン/ログアウト)

### 3.2 フロントエンド機能
- [ ] レイアウト、ナビゲーションの実装
- [ ] プリセット設定画面（イベント名保存）
- [ ] カメラコンポーネント実装（OCR API呼び出し含む）
- [ ] 属性選択・フォーム入力コンポーネント
- [ ] 訪問者リスト表示（フィルタリング機能）

### 3.3 バックエンド・連携機能
- [ ] 訪問者登録 API (`/api/visitors`)
- [ ] Sansan API 連携ロジック（タグ付け、画像送信）
- [ ] UTAGE API 連携ロジック（配信リスト追加）
- [ ] メール配信・体験URL生成ロジック (`/api/send-emails`)

### 3.4 非機能・品質
- [ ] IndexedDBを活用したオフライン保存・同期機能
- [ ] 各画面のモバイルレスポンシブ対応
- [ ] エラーハンドリング・例外系UIの実装

## 4. リスク管理計画

| リスク | 影響 | 対策 |
| :--- | :--- | :--- |
| **不安定な通信環境** | データの消失、APIエラー | IndexedDBによるローカル一時保存と、復帰時のバックグラウンド自動同期。 |
| **OCR解析精度の低さ** | 誤ったデータ登録 | 撮影画像のSupabase Storage保存によるバックアップ、および音声/手動入力による補完。 |
| **API制限 (Rate Limit)** | Sansan/UTAGEへの登録失敗 | 送信キューの導入、リトライメカニズムの実装、およびエラー通知ダッシュボード。 |
| **デバイス互換性** | カメラや音声入力が動作しない | 主要なiOS/Androidブラウザでの実機テスト徹底、フォールバック（手動アップロード）の用意。 |

## 5. 運用方針
- **デプロイ**: VercelのGitHub連携によるCI/CD。
- **監視**: Vercel Analytics および Supabase Logs によるパフォーマンス/エラー監視。
- **不具合対応**: 展示会期間中は専任エンジニアがオンコール体制をとり、緊急メンテナンスに備える。
